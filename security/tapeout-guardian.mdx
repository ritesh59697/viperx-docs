ViperX does not trust a trading agent to respect its own risk limits. On OKX X Layer mainnet (chain ID `196`), every trade is checked by four **TapeOut digital logic circuits** before it touches vault liquidity. The limits are not Solidity constants: each one is built into the gates of a NAND netlist that lives on chain, in a TapeOut processor created through the official TapeOut factory.

If any circuit fails, the trade reverts with `CircuitRiskRejected(diagnosticBits)` and no funds move. The diagnostic bits say which check failed.

## The four circuits

All four circuits are on one processor, **ViperX Risk Guardian** (`VXRG`):

```text
0xb57b56034e2dc25161e2512CfC40b24EA3bee1Fb
```

| Circuit ID | Check | Passes when | Input | NAND gates | Fail bit |
|---|---|---|---|---|---|
| `1` | `leverage_le` | leverage ≤ 20.00x | leverage × 100, 16-bit | 38 | `1` |
| `2` | `slippage_le` | slippage ≤ 2.00% | basis points, 16-bit | 41 | `2` |
| `3` | `drawdown_le` | drawdown ≤ 25.00% | basis points, 16-bit | 37 | `4` |
| `4` | `cooldown_ge` | ≥ 10 s since the agent's last trade | seconds, 16-bit | 42 | `8` |

[View the processor on OKLink](https://www.oklink.com/xlayer/address/0xb57b56034e2dc25161e2512CfC40b24EA3bee1Fb)

Each circuit is a 16-bit comparator against a constant built into the netlist, about two NAND gates per input bit. `x ≤ K` is scanned from the least significant bit up; `x ≥ K` is built as `NOT(x ≤ K − 1)`.

## How a trade is checked

```text
trade (size, collateral, limit price, agent)
      |
      v
TapeOutCircuitGuardian.computeSignals         full-width integers
      |  leverage x100 | slippage bps | drawdown bps | seconds since last trade
      v
TapeOutSignal.encode(value, nIn)              capped at 2^nIn - 1, packed LSB-first
      |
      +--> processor.eval(1, leverage)  --> 1 = pass / 0 = fail --> bit 1
      +--> processor.eval(2, slippage)  --> 1 = pass / 0 = fail --> bit 2
      +--> processor.eval(3, drawdown)  --> 1 = pass / 0 = fail --> bit 4
      +--> processor.eval(4, cooldown)  --> 1 = pass / 0 = fail --> bit 8
      |
      v
all four pass --> trade reaches ViperVault
otherwise     --> revert CircuitRiskRejected(diagnosticBits)
```

Both trade paths are gated:

| Caller | Entry point | Guardian call |
|---|---|---|
| A trader on [viperx.site/trade](https://www.viperx.site/trade) | `ViperVault.openPosition()` | The vault calls the guardian before opening the position. |
| An AI agent with a signed EIP-712 intent | `PositionRouter.executeAgentIntent()` | The router calls `validateIntent()`; the vault then skips its own check so one trade is never counted twice against the cooldown. |

<Note>
  Direct trades from the UI name no limit price, so they report zero slippage rather than an invented value. Drawdown is set per agent by the router or the owner.
</Note>

## Reading a rejection

`CircuitRiskRejected(uint32 diagnosticBits)` sets one bit per failed check:

| Bits | Meaning |
|---|---|
| `1` | Leverage above 20.00x |
| `2` | Slippage above 2.00% |
| `4` | Drawdown above 25.00% |
| `8` | Less than 10 seconds since the agent's last trade |

Several checks can fail at once: `CircuitRiskRejected(9)` means leverage and cooldown both failed.

## Design choices that make the gate safe

<AccordionGroup>
  <Accordion title="Inputs are capped, never truncated">
    The guardian computes each signal at full width, then `TapeOutSignal.encode` caps it at the circuit's all-ones input (65,535 for 16 bits). Truncating would wrap: 655.37x leverage (65,537) would reach a 16-bit circuit as `1` and pass. The generator refuses any ceiling of 65,535 or more, so capping never changes a verdict.
  </Accordion>
  <Accordion title="A half-configured gate refuses every trade">
    With no circuits set, the guardian is inactive. With one to three set, every trade reverts `IncompleteCircuitSet`, so a misconfigured gate cannot quietly skip a check.
  </Accordion>
  <Accordion title="Only real TapeOut processors are accepted">
    `setCircuit(check, processor, circuitId)` accepts a processor only if the TapeOut factory reports it as its own (`isCPU`), and only circuits with one output and no latch state. The input width is read from the processor, not assumed.
  </Accordion>
  <Accordion title="The circuit is the binding limit">
    The vault's own per-market cap is 25x, five above the leverage circuit's ceiling. A 22x trade is therefore stopped by the circuit (`CircuitRiskRejected(1)`), not by the vault.
  </Accordion>
  <Accordion title="Every netlist is checked against every input">
    The netlists are generated by `contracts/tapeout/gen_comparator.py`. Before a file is written, the generator evaluates it with the TAP-02 reference evaluator and compares it with plain integer comparison for all 65,536 inputs. At deploy time, `TapeOutWiring.sol` refuses any circuit whose on-chain netlist differs from its generated file.
  </Accordion>
</AccordionGroup>

## Proof on mainnet

Two trades on 2026-11-16, ETH-PERP, $1,000 demo collateral:

| Trade | Result | Transaction |
|---|---|---|
| 5x long | Passed all four circuits; position opened (815k gas) | [`0x146510d1…46d3ed`](https://www.oklink.com/xlayer/tx/0x146510d1aa8449a7752785c8090fde5f28daf98f4ce4341aeb91e7738046d3ed) |
| 25x long | Reverted `CircuitRiskRejected(1)`: the leverage circuit failed, while the vault's own 25x cap would have allowed it | [`0x35170db2…3fd094`](https://www.oklink.com/xlayer/tx/0x35170db2344b09f3ff96146ea38a2652e4680e7abbe1b2ed46acaddad73fd094) |

You can repeat the check yourself on [viperx.site/trade](https://www.viperx.site/trade): connect an OKX Wallet on X Layer, claim demo USDC from the faucet, open a 5x long, then try 25x. The second order is refused with *"blocked by the on-chain risk circuits: leverage check failed"*.

### Check a circuit directly

`processor.eval` is a read call, so you can query a circuit without a wallet. Leverage is encoded as leverage × 100, little-endian:

```bash
# 20x = 2000 = 0x07d0 -> bytes d0 07 -> passes, returns 0x01
cast call 0xb57b56034e2dc25161e2512CfC40b24EA3bee1Fb "eval(uint256,bytes)(bytes)" 1 0xd007 --rpc-url https://rpc.xlayer.tech

# 25x = 2500 = 0x09c4 -> bytes c4 09 -> fails, returns 0x00
cast call 0xb57b56034e2dc25161e2512CfC40b24EA3bee1Fb "eval(uint256,bytes)(bytes)" 1 0xc409 --rpc-url https://rpc.xlayer.tech
```

## Source code

The contracts and circuits are open source in the [ViperX repository](https://github.com/ritesh59697/ViperX):

- `contracts/src/core/TapeOutCircuitGuardian.sol`: the guardian
- `contracts/src/libraries/TapeOutSignal.sol`: the capping encoder
- `contracts/tapeout/circuits/`: the four generated netlists
- `contracts/tapeout/gen_comparator.py`: the netlist generator

## DeWEB package

The ViperX verification portal and an interactive circuit simulator are packaged as a self-contained TapeOut DeWEB (TAP-10) container, built with `bun run build:deweb`. The package is **built but not yet published** on DeWEB.
